> **2026-11-21 authority-model update:** The owner has selected an explicit no-concurrent-writers maintenance window for this NAS. Maintenance mode no longer asks the strict custody issuer for proof; it requires a literal acknowledgement bound to each WorkJob and keeps the NFC lock, Worker lease and pinned inode scope for execute/cleanup/recovery. This is a weaker operational contract, not strict OS isolation. Strict mode remains deny-only. The owner-observed root OpenList/Rclone writers remain able to access the SATA tree and must stay idle. See [operating contract](v16-maintenance-window-operating-contract.md). This update supersedes earlier statements in this historical packet that both modes require external custody.

### Baseline name-boundary experiments

All experiments used disposable local temporary directories as actual non-root UID 1000. They did not access a NAS. The baseline maintenance authority was not replaced with a permissive custody fixture for the operation being examined.

- Replacing an original file immediately before the final unlink removed the foreign replacement. The earlier verified original remained at the test's detached path.
- Replacing an already-empty old wrapper immediately before rmdir removed the foreign empty directory. In the observed run cleanup still returned `finalized=true`, `already_organized=true`, and zero moves/renames. A successful rescan cannot retrospectively prove that a foreign object was never deleted.
- Replacing the newly created public group before its first open with an empty same-UID 0700 directory caused that replacement to receive ownership/completion witnesses and a published media link. Post-open checks captured the replacement's inode.
- Replacing a new stage before its first open likewise allowed adoption. A populated replacement received an owner witness and staged link before later inventory rejection. Before durable cleanup-plan stage binding, a replacement containing copied witnesses and authentic hardlinks could also be adopted on a new maintenance session.

These are stronger observations than a synthetic callback that announces revocation. Repeating inode checks or requiring the callback to raise does not prevent a writer that changes child names while the original maintenance session remains valid.

The regression hold tests retain the last-syscall injections and require the real production issuer to refuse before reaching them. They verify originals, directories and private evidence remain unchanged and no cleanup journal is created. Separately, valid synthetic custody tests continue to cover actual publication, cleanup and recovery algorithms.

### Descriptor opens and content limits

Three deterministic tests changed a planned regular source or stage witness into a FIFO immediately before `open`. The baseline blocking read stalled until the test alarm. `O_NONBLOCK` now permits the existing `fstat` regular-file validation to reject promptly; no file-content operation or new source-name fallback is introduced.

The source-name swap test at the actual proc-FD linking syscall still linked the authentic opened inode. This is an inode identity guarantee, not immutable content. A same-inode equal-length write followed by restored mtime passed baseline metadata checks. `cleanup-audit` and shared snapshots explicitly report `file_content_hashes_verified=false`; do not describe these checks as original/stage/final payload-hash verification.

Manifest, plan and journal SHA-256 values are integrity bindings under trusted file/config permissions. They are not keyed digital signatures. Historical wording such as “Worker-signed” should not be read as a cryptographic signing claim.

## Authority changes and recovery boundaries

1. API eligibility for either mode obtains an external proof and releases it after the eligibility check. All execution plans, including flat plans, pass this check. Preview confirmation tokens use the same rule.
2. A queued or recovered Worker acquires its own resource before staging or writing execution evidence. It never reuses an API-time observation as a grant.
3. A maintenance session holds that proof inside its `ExitStack`, alongside its cooperative lock and pinned directories, and refreshes it at existing mutation fences. Closing or revoking the proof prevents further operations.
4. Cleanup and cleanup recovery use the same eligibility/acquisition boundaries. Read-only historical handoff snapshots remain accessible. Returning an existing already-approved job without creating or running work remains distinct from authorizing a new mutation.
5. Frozen mode, plan, ancestry, journal and checkpoint fields are unchanged. The patch does not relabel maintenance evidence as strict evidence, regenerate a plan after retirement, clear reservations, delete retained stages or invent finalization.

The current production issuer is deliberately unavailable. Therefore this head is ready to be examined as a contained, fail-closed candidate, **not a functionally authorized production V1.6 release**. A supported implementation must establish the required mount/inode, principal, namespace and content-write exclusion scope and revocation/lifetime semantics before the hold can be removed. Positive fixture providers are never installed in production code.

## Worker probe repair

The baseline had three initial reproducible lease-expiry failures: expiry after the capability checkpoint, expiry after validation progress, and expiry after the first scratch creation. Later probe creates/links occurred despite expiry; the validation case changed plan items to validated before the final WorkJob checkpoint detected lease loss. An additional test isolates expiry immediately before the plan-result transaction. Two legacy executor tests cover the same nested boundary.

Probe functions now accept an optional mutation fence. Worker callers pass active-lease assertions, and the newly routed jobs also verify cooperative lock and maintenance reservation. Fences precede scratch create/write, hardlink, clone ioctl, mutation-related fsync, and unlink. Authority exceptions propagate; they are not converted into “unsupported filesystem” results.

If authority expires after a scratch object was created, the stale Worker stops and retains that object. It does not unlink it without authority. These leftovers are explicit evidence; this patch adds no blind cleanup or automatic retry. Final plan persistence checks the active Worker lease and reservation within `BEGIN IMMEDIATE`, explicitly flushes pending writes, then checks lease validity again before commit. Lease renewal samples time after obtaining SQLite's writer lock so time spent waiting cannot revive an expired lease. Both storage validation and the media-sort validation Worker supply their Worker identity. The storage validation handler reuses the Worker's session factory instead of invoking the API constructor and its unrelated startup quarantine reconciliation. Ordinary plans retain their synchronous API contract; disabling mutation produces the existing storage-plan refusal without scratch writes.

A separate patch reviewer found that failed hardlink creation (including `EEXIST`) unconditionally attempted to delete the destination. The repair never cleans a destination that was not created, compares owned FDs before cleanup, opens the linked read descriptor with `O_NOFOLLOW | O_NONBLOCK`, verifies its type/inode and limits reads to the tiny expected payload plus one byte. These checks alone cannot make final unlink atomic. Storage probes therefore also need a held, refreshed, scoped external-custody resource. Their production issuer is unavailable: actual capability requests return `unknown` with the custody reason before creating scratch, and storage-plan validation cannot claim support. No environment flag supplies this resource. Explicit temporary-directory test providers exercise the retained probe algorithm and release/revocation behavior.

Legacy storage-optimization recovery previously bypassed initial probes once a `.new`, `.old` or published state existed. Three interrupted-state experiments confirmed that recovery still changed media and journals after restoring the unavailable live provider. The executor now separately acquires and holds custody over the opened source/keep parent identities before any mutating branch; media mutations refresh both lease and proof, and journal commits refresh the proof without opening a nested lease-renewal transaction. Fresh-source identity/hash/link-count preflight and completed read-only reconciliation retain their original behavior. A probe refusal cannot be bypassed by resuming an older transaction. This extends the current production hold to new storage optimization and its mutating recovery, while preserving retained evidence and completed read-only review.

The shared proof acquisition rejects two FDs with different dev/inode values for the same parent path; it cannot silently replace one binding in its scope map. Executor journal transactions keep their existing lease assertion at entry and add a custody check before commit. The new explicit post-flush lease check described above applies to validation results, not to every existing journal transaction.

The legacy executor's read-only KEEP/SOURCE inspections run before custody admission. Their regular-file opens now also use `O_NONBLOCK`, retaining `O_NOFOLLOW` and type checks, so an unavailable issuer does not leave the Worker hanging at an earlier substituted FIFO. Both actual-open substitution tests failed by bounded alarm before the fix and passed afterward with original files and journals unchanged.
