## Audit findings

### Responsive gaps

Fresh source search found no shared:
- `useBreakpoint`,
- CSS `@media` contract,
- mobile navigation Drawer,
- `ResponsiveDataView`.

The shell is desktop-first: sidebar is always mounted, content has desktop margins, header action clusters assume horizontal room.

### Styling fragmentation

Representative pages rely heavily on inline styles. Spacing, radii, surfaces and colors are duplicated across shell, Dashboard, Settings and operational pages. This blocks global responsive rules and makes light/dark parity hard to audit.

### Status fragmentation

Strengths:
- `STATUS_MAP`
- `SafeModeBadge`
- `WorkerStatusBadge`
- explicit destructive confirmations

Gaps:
- status presentation is split across Tag presets and local colors,
- lifecycle and risk levels lack shared visual primitives,
- legacy status map does not yet model every current state such as `expired`.

### Mobile risk

Primary pages contain wide Tables, Descriptions, action groups, long absolute paths and dense technical text. Generic horizontal scrolling is rejected for primary workflows.

### Legacy chrome

Sidebar still displays `v0.3.5 Enterprise`.
The UI mixes arbitrary radii and page-local colors.

## Frozen decisions

### Keep Ant Design 5

Retain Ant Design 5 for v0.4.0.

Reasons:
- mature forms/tables/modals/drawers,
- existing behavior is integrated,
- lower functional regression risk,
- design goals can be reached with tokens, CSS variables and NFC wrapper components.

MUI migration is not a success criterion.

### Add project-owned design layer

Add:
- root `DESIGN.md`,
- semantic CSS variables,
- responsive hooks/primitives,
- shared status/safety primitives,
- shared page layout/data primitives.

AntD becomes an implementation detail below the product design layer.

### Preserve business architecture

C1 requires no route/backend API changes.
Do not alter executor, Worker, Plan lifecycle, filesystem operations, Quarantine transaction semantics, PathGuard or mutation authority.
